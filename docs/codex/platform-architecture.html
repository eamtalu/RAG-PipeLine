Proposed for review

Data to decisions, without losing control.

A single-host-first architecture for processing more than one million log rows per day, training and comparing predictive models, serving real-time risk signals, and operating copilots through explicit policy and approval boundaries.

1M+ rows / day 90M to 180M retained rows Real-time + batch Single host to multiple hosts Architecture only
01 / Decision

One platform, two data planes, isolated workloads.

01
Operational core

PostgreSQL remains the system of record, serving store, durable job control plane, prediction ledger, and audit index.

02
Analytical lane

Verified Parquet datasets and an object-store interface isolate historical scans and training from live API workloads.

03
Independent roles

Ingestion, stitching, scoring, training, archive, notification, and actions run as separate supervised processes.

⚠
Action execution is blocked until authentication and RBAC exist. The current copilot should remain read-only. The target design supports proposals and approvals, but infrastructure execution cannot safely ship under the current identity model.

Bronze

Raw, lossless, append-only

Time-partitioned entries preserve replay, deduplication, provenance, and late-arriving evidence.

Silver

Operational entities

Deterministic transactions serve APIs and provide stable entity IDs for features and predictions.

Gold

Purpose-built datasets

Versioned failure, duration, demand, anomaly, and root-cause datasets use point-in-time contracts.

Decision

Models and governed action

Registered models produce auditable predictions, incidents, recommendations, and approved playbooks.

1. Freeze

One point-in-time dataset, manifest, checksum, and chronological split.

2. Tournament

Baseline and bounded candidates train against identical evidence.

3. Shadow

Measure latency, drift, calibration, and alert volume without operational impact.

4. Promote

Approve an immutable version and retain the previous champion for rollback.

04 / Agent safety

Reason freely. Execute only through policy.

stateDiagram-v2
  [*] --> Proposed
  Proposed --> Recommended: recommend only
  Proposed --> AwaitingApproval: approval required
  Proposed --> Authorized: pre-approved low risk
  AwaitingApproval --> Authorized: approved and unexpired
  AwaitingApproval --> Rejected: rejected or expired
  Authorized --> Executing: policy revalidated
  Executing --> Succeeded: postcondition passed
  Executing --> Failed: error or postcondition failed
  Failed --> Escalated: notify human
Recommend

The agent records evidence and advice. No executor is invoked.

Human approval

An authenticated approver grants exact, expiring scope before execution.

Pre-approved low risk

Only named playbooks operate inside strict blast-radius, cooldown, and rate limits.

06 / Review

Ten decisions unlock implementation planning.

1
Approve PostgreSQL plus Parquet/object storage as the initial operational and analytical split.
2
Approve failure-risk prediction as the first production ML use case.
3
Choose tenant-specific, global, or hybrid model scope.
4
Set the false-alert budget, recall target, and scoring latency budget.
5
Define a root-cause taxonomy and label owners.
6
Choose the initial hot-retention period between 30 and 90 days.
7
Approve the proposed ML and action control-plane entities.
8
Approve authentication and RBAC as execution prerequisites.
9
Name the first pre-approved low-risk playbooks.
10
Approve the phased roadmap and release gates.
